# 대전 핫 기믹 쾌락천 한글화 — 초기 조사 (2026-09-29)

상태 표기: **확정** = 소비자/런타임으로 검증, **후보** = 정적 증거만, **미해결** = 다음 진단 필요.
전작 프로젝트(`../taisen1`, MAME `hotgmck`)의 조사 결과를 가설로 두고, 이 리비전에서 다시 확인한 것만 적는다.

## 1. 입력 (지원 리비전)

- MAME 세트 `hgkairak` "Taisen Hot Gimmick Kairakuten (Japan)", MAME 0.289 `romset hgkairak is good`. **확정**
- 하드웨어: 전작과 같은 `psikyo4` 드라이버 (SH-2 28.6MHz, YMF278B, 320×224 화면 2개, 마작 패널).
- 파일 17개, 크기·SHA1은 `tools/hgkairak/source.py`. 전작과 다른 점: 파일 이름(`1.u22`, `2.u23`, `prog.u1`, `0l.u2`…`5h.u16`, `snd0.u10`, `snd1.u19`), `prog.u1` 1MB, 그래픽 6쌍 48MB.

## 2. 주소 배치 (확정 — 런타임 스프라이트 RAM과 렌더 비교)

- 메인 CPU 이미지 `0x000000-0x0FFFFF`: 32비트마다 `1.u22` 워드(바이트 스왑) ‖ `2.u23` 워드(바이트 스왑). 전작과 같음.
- 그래픽 `gfx1` 48MB: 8MB 쌍 k마다 32비트 = `kl` 워드 ‖ `kh` 워드. 타일 16×16 8bpp = `tnum × 256`.
- 메인 이미지 `0xC8000` 이후는 `0x8000` 주기 반복(원본 특성). 코드가 참조하는 것은 첫 사본.
- 스프라이트 목록 `0x03002C04`, 항목 비트 `0x2000` = 화면 선택(0=1P, 1=2P), `0x4000` = 끝. 2P 화면은 색 번호에 0x20이 더해짐.

## 3. 대사 (확정)

- 글꼴 코드 체계는 전작과 같은 JIS X 0208 압축 순서. **글꼴 타일 기준 `0x18788`**(전작 `0x1481E`), 글리프 `0x000-0xD65`.
- 추가 한자 `0xD38-0xD65` 46자: 전작 목록에 `綺`(0xD5A)·`腑`(0xD5C)가 끼어 있음 — 타일을 눈으로 판독(**후보**, 원문 대조로 `綺麗` 확인).
- 문자열 블록 메인 `0x7881C-0x7FDE4`, 686개, 9,326 글리프, 서로 다른 글자 615종. 형식은 전작과 같음(`FFFE` 줄바꿈, `FFFD` 빈칸, `FFFF` 끝, 4바이트 정렬).
- 포인터 표 `0x7741C-0x78818`(32비트 절대 주소). 참조되는 문자열 461개, **미참조 225개**.
  - 미참조 문자열은 캐릭터별 대사 표(`0x78400~`, 캐릭터마다 16칸)의 빈 칸(0)과 정확히 대응 → 쓰이지 않는 초기 데이터로 판단(**후보**). 번역은 모두 넣었고 표에 "포인터 미참조" 메모.
- 빈칸 타일: `FFFD`가 그리는 타일은 `0x2512`(글꼴 밖).
- PoC: `対戦モードを選ぶッス！`(`T07F344`)를 한글로 바꿔 모드 선택 화면에서 표시 확인. 이후 686개 전체 적용 빌드를 자동 플레이로 확인(모드 선택, 캐릭터 소개, 힌트 대사).

## 4. 그림 글자 (graphics text)

### 4.1 스프라이트 서식 표 (확정)

- 메인 `0x70000-0x77000` 부근. 8바이트 = `h-1|플래그(bit27)|y|w-1|x`, `색|플래그|tnum` — 전작과 같은 배치지만 **표가 4 mod 8 주소에서 시작**(`0x70434` = 코인 문구 12×2 등).
- 색 뱅크 6 팔레트 = 메인 `0x68BD0` (관측한 모든 장면에서 팔레트 RAM과 같음), 뱅크 8(모드 선택) = `0x6A190`.

### 4.2 타이틀 로고 (적용)

- 로고는 1×1 스프라이트 20×14 격자. 타일 배치는 메인 `0xC0F88` 헤더(타일 기준 `0x20000`, 14행, 380열 = 19프레임 × 20열)의 열 우선 16비트 표, 헤더 포인터는 `0xB73B8`.
- 19프레임 = 빈 화면 / ホットギミック 확대 흐림 → 선명 / 빈 화면 / 快楽天 같은 방식 / 빈 화면 / 타원+対戦 페이드(α .3 .6 1) / 두 조각이 위아래에서 모임 / 흰색 섬광(.6 .3) / 완성.
- 19프레임 전부가 연속 타일 `0x2BA5F-0x2C08E`(1,584개)만 쓰고, 다른 스트립(`0xBE5F0`: `0x28271-0x28BF3`)·서식 표·런타임 관측에서 이 범위를 쓰는 곳 없음 → 전용 영역으로 판단.
- 빌드(`tools/hgkairak/title.py`): 한글 로고 3개 층(타원+대전 / 핫기믹 / 쾌락천)으로 같은 연출의 19프레임을 합성 → 원본 팔레트(`0x6A590`)로 양자화 → 타일 중복 제거 후 풀에 재배치 → 19개 배치표 재작성. 현재 1,584/1,584 타일 사용(여유 없음, 넘치면 빌드 실패).
- 층 분리: `tools/derive_title_layers.py`가 사용자 제공 `assets/gfx/title_ko.png`에서 배경 제거·글자 분리·가려진 타원 복원(재합성 차이 1.6%, 글자 가장자리). 타원만 보이는 프레임(11-15)은 원본처럼 단색 녹색.
- MAME에서 19프레임 연출과 완성 화면 확인.

## 5. 제품 빌드 경로

```
python3 tools/khpatch.py extract --source roms/hgkairak.zip   # translation/dialogue.json 생성·병합
python3 tools/khpatch.py build   --source roms/hgkairak.zip   # out/hgkairak.zip + out/manifest.json
python3 -m pytest -q tests
```

전작과 같은 쓰기 계획(원본 기대 바이트, 겹침·보호 범위·설명 안 되는 차이 검사, 전부 아니면 전무). 번역 표와 그림 글자 표가 비어 있고 그림 자산을 지정하지 않은 빌드는 원본 17개 파일과 바이트 단위로 같음(2026-09-29 확인, 쓰기 0건).
